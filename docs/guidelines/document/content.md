# 文档内容

文档按照**对象**而非主题/机制进行分类，规则和数据分离。例如，顿悟系统位于 `玩法设计 - 玩家发展 - 顿悟系统`，而具体的顿悟内容则位于 `资料库 - 顿悟`。这种分类方式有利于文档的维护和扩展。

而每一个对象本身也可以包含其他子内容。例如，法术系统可以包括法术升级、法术获取等子内容，而这些子内容也可以单独作为对象。

文档共有 8 个部分，分别是：
- 项目概览 `project` 
- 玩法设计 `design`
- 世界设定 `world`
- 内容叙事 `content`
- 资料库 `library`
- 技术实现 `development`
- 开发规范 `guidelines`
- 杂项 `appendix`

### 项目概览
项目概览是整个项目的入口，回答“我们要做什么？”的问题，介绍项目是什么、核心玩法循环以及项目的整体规划，方便新成员快速了解项目。

项目概览也是在开发过程中面向大众的窗口，让玩家对我们的项目有一个总体的理解。

典型内容包括：
- 项目概览
- 核心玩法循环
- 设计支柱
- 命名规范
- 更新日志

### 玩法设计
玩法设计记录了所有游戏机制，回答“游戏如何运作？”的问题。需要注意的是，玩法设计文档只记录游戏机制的设计，而不涉及具体的内容。具体内容会在内容叙事和资料库中进行记录。

典型内容包括：战斗、玩家成长、探索、经济、任务、UI/UX、多人游戏等。

### 世界设定
世界设定包括了世界观、历史、地理、种族、文化等内容，回答“世界是什么样子？”的问题。

### 内容叙事
内容叙事记录了玩家实际会游玩的内容，包括任务树、剧情、演出、地图关卡设计等。这里会涉及到具体的内容设计，回答“玩家会遇到什么？”的问题。

### 资料库
资料库记录所有的实体 `Entity`，即游戏中有哪些内容，包括法术、装备、Boss、结构等。  

所有内容的最终呈现均以资料库为准。

相较于文档，资料库更像是百科，记录了对象实体的数据，而不解释这些对象是如何运作的。

### 技术实现
技术实现记录了技术的实现方式，也就是技术栈与工程实践，例如 魔改、世界生成、演出、UI、自制模组等内容。

### 开发规范
开发规范记录了团队的开发约定，例如：
- 文档编写规范
- Git 工作流
- 开发环境的部署与管理
- AI / 彩蛋 内容披露规范

### 杂项
杂项里放置补充资料和其他内容。例如：
- 名词解释
- 外部参考
- 废案
- 灵感池

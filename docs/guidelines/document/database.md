# 数据库与自动引用

资料库中的部分结构化内容使用 SQLite 维护。数据库保存日常编辑的数据，构建脚本根据数据生成索引、详情页和侧栏条目，最后由 VitePress 构建静态网站。访问网站时不需要数据库服务。

不同业务可以使用不同的数据库或数据表，各自的字段和编辑要求记录在对应的维护说明中。

## 日常编辑

1. 使用 DB Browser for SQLite 等图形工具打开对应数据库。
2. 选择业务表，按其维护说明编辑记录。
3. 写入修改，关闭数据库连接。
4. 本地检查或构建，确认页面内容后提交数据库文件。

每张业务表使用稳定的 `id` 标识记录，显示名称使用 `name`。改名时保留 `id`，以保持引用和详情页地址稳定。不同表可以使用相同 ID，引用通过表名区分。

SQLite 文件不能自动合并行级改动。协作时避免同时修改同一个文件；发生冲突时，在一份数据库中重新应用双方的记录修改。

## 自动引用

引用格式为 `[[表名:ID]]`，需要自定义显示文字时使用 `[[表名:ID|显示文字]]`。表名是站点已接入的业务表名，与数据库文件名分别维护。

例如：

```md
需要使用 [[arcane_materials:sulfur]]。
也可以使用 [[arcane_materials:sulfur|硫晶]] 自定义显示文字。
```

默认显示记录的当前名称，并链接到对应详情页。已接入的 Markdown 文本字段也可以使用引用；具体字段见各表的维护说明。代码和数学公式中的文字不解析为引用。

表名尚未接入或 ID 不存在时，校验和构建失败。Markdown 表格中的自定义文字分隔符需要转义：`[[arcane_materials:sulfur\|硫晶]]`。

## 构建与检查

需要 Node.js 24，首次使用先安装依赖：

```sh
npm ci
npm run docs:dev
npm run docs:build
```

开发和生产构建会先执行已接入的数据生成步骤。开发服务器启动后修改数据库，需要写入数据并重启开发服务器，重新生成页面、侧栏和搜索索引。

当前材料表可以单独检查：

```sh
npm run materials:check
```

## GitHub Actions 变更报告

提交后，Actions 校验已接入的数据与引用、执行测试并构建站点。变更报告写入 `.report/`，展示在运行摘要中，并作为工件提供下载。

- PR 比较共同祖先与 PR 分支当前提交。
- 推送比较推送前后。
- 手动运行比较前一个提交与当前提交；没有前一个提交时按空数据库比较。
- 基准提交没有对应数据库时，当前记录全部视为新增。

报告按稳定 ID 对比记录：新增和删除展示全部字段，修改展示字段的旧值与新值。已登记的材料 ID 迁移会显示 ID 的旧值与新值，其他 ID 改动表现为删除旧记录和新增记录。多选字段是否按集合比较，由对应业务的报告规则决定。

当前材料报告的命令与产物为：

```sh
npm run materials:report
npm run materials:report -- --base HEAD~1 --head HEAD
```

默认输出 `.report/materials-report.md`，Actions 工件名为 `materials-report`。新增业务应使用独立的报告文件名，避免相互覆盖。

## 接入新的数据库或数据表

新增业务时需要一并完成以下内容：

1. 确定数据库文件、业务表名、稳定 ID 和字段结构，编写维护说明。
2. 接入数据读取与校验，包括必填项、选项和字段类型。
3. 确定索引页、详情页和侧栏位置，接入页面生成。
4. 扩展引用解析器，使新表名能够解析到记录名称和详情页地址。
5. 接入变更报告、构建命令与 Actions，并更新本页的已接入数据表。

当前材料实现可参考 `scripts/materials-lib.mjs`、`scripts/materials.mjs`、`scripts/material-references.mjs` 和 `scripts/materials-report.mjs`。其中仍有材料表专用规则，新增业务时需要明确扩展，不能直接复用材料的字段选项或页面路径。

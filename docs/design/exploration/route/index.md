# 航线与航标系统

Minecraft 的开放世界有着极大的地图尺寸，但对于冒险整合包而言，长距离移动往往意味着大量重复且缺乏内容的跑图时间。《航迹》以群岛和海洋作为世界背景，不同的区域之间被海洋分割，如果仍采用传统方式航行，玩家需要花费大量时间穿越几乎没有玩法的海面，严重影响游戏节奏。

诚然，Minecraft 确实可以通过 `/locate` 指令或结构指南针等方式实现快速传送，但我们需要为不希望打开作弊权限的玩家提供一种合理可行的规避垃圾时间的方法。航线与航标系统就是为此而生的。

航线与航标系统的核心目标并非“缩小世界”或“抹除海洋”，而是在保留海洋作为世界重要组成部分的前提下，减少没有设计价值的移动时间。玩家应尽快进入真正的游戏内容，而不是长时间航行于缺乏交互的空白海域。

## 航线系统

航线系统是要塞生成机制与传送石碑的结合体。世界生成时，会在世界中生成有限个港口结构，并记录于 `LevelData` 中。玩家可以通过地图查看这些港口的位置，并实现以下两种传送：
- 港口 <-> 港口：在任意自然港口之间传送。
- 舰队 --> 港口：玩家从舰队传送至港口。

此外，玩家也可自行设置额外的传送点，作为港口的补充。

### 港口机制

自然生成的港口结构会在世界生成时确定位置，默认处于未激活状态。

> **未激活的港口仍然可以直接传送。** 激活并非传送的前置条件，而是传送（或抵达）后的结果。当玩家首次抵达港口附近，或成功传送至该港口（无论激活与否）时，港口即被激活。

在多人模式下，激活与否的判断以舰队而非玩家为单位，同一舰队旗下的所有玩家共享港口激活进度。

### 传送机制与小游戏

在传送时，游戏会判断目标传送点是否已被激活：
- **已激活**：直接传送，流程结束。
- **未激活**：传送照常执行，到达后触发激活小游戏。

小游戏只有奖励没有惩罚（或只有微小的惩罚），一方面是为了让玩家在传送时有一定的参与感，另一方面是为了优化区块加载时的体验。小游戏的等级会根据玩家的传送距离和传送点的等级来决定，等级越高，小游戏时间越大，奖励也越丰厚。

在传送完成后，会有5分钟的冷却时间，防止玩家频繁传送。

传送流程如下：
``` mermaid
flowchart TD
    A[玩家选择目标传送点<br>（自然港口 / 自制传送点）] --> B{系统检查目标传送点<br>是否已被激活？}
    B -- 是（已激活） --> C[直接执行传送]
    C --> D[传送完成，流程结束]
    
    B -- 否（未激活） --> E[执行传送]
    E --> F[传送完成，触发港口激活小游戏]
    F --> D
```

需要注意的是，因为加载区块的时间较短，小游戏的时间不宜过长，不应该使用过于复杂的系统或者关卡设计。实际设计可以参考 Chrome 浏览器的离线小游戏，或者吃豆人等经典街机游戏。


::: info 灵感：航行许可
一个面向未来的小想法，现在的设计是所有的港口默认都是可见的，玩家可以自由传送。未来可以考虑加入航行许可的概念，玩家需要达到一定的阶段才能发现部分港口并传送。这样可以让玩家有更多的探索和成长空间。  
:::

## 航标系统
航标系统是末影之眼或结构指南针的替代方案。航标专注于定位功能，玩家可以通过航标确定目标结构的坐标，并在地图中显示出来。玩家可以传送到航标附近的港口减少跑图的时间。

## 后续扩展

为了保证初始版本的开发效率，航线系统目前仅承担区域连接与快速航行功能。未来可以在保持现有框架不变的基础上，逐步扩展更多玩法，例如：

- 舰队系统：快速航行由舰队执行，不同舰船影响航行速度、载货量或特殊能力。
- 资源经营：港口可升级，为舰队提供更多服务、航线或补给能力。
- 贸易网络：不同港口拥有独特资源，玩家可建立稳定的海上贸易路线。
- 海上事件：快速航行过程中可能遭遇随机事件、特殊奖励或限时挑战，丰富远航体验。
- 世界推进：新的航线、港口和群岛可随剧情或玩家成就逐步开放，形成持续扩展的探索版图。
